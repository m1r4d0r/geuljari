# 글결 — 글 입력에서 첫 안까지

## 반영한 방향

첫 화면은 입력창, 분위기 선택, 두 가지 선택 사항과 시작 버튼으로 구성합니다. 사용자가 내용을 놓고 몇 가지 의도만 정하면 첫 안을 보여 주고, 속도·쉼·등장 방식·바탕 조절은 결과 화면의 ‘다듬기’에서 엽니다.

- 분위기는 건너뛰거나 최대 두 개를 조합합니다. 따뜻한·서늘한·고요한·아련한·팽팽한·가벼운은 이번 시안에서 제안하는 어휘이며 확정된 목록은 아닙니다.
- 강조하고 싶은 문장과 분위기가 바뀌는 시작 문장은 원문에서 직접 고릅니다. 따로 고르지 않고 첫 안을 볼 수도 있습니다.
- 원문을 고치면 위치가 잘못 적용되지 않도록 기존 강조와 전환 선택을 초기화합니다.
- 첫 안에서는 읽는 모습을 크게 보여 주고, 세부 조절과 생성 이유는 처음에 닫아 둡니다.
- 마스킹을 입력 단계에서 요구하지 않습니다. 원문은 브라우저 메모리 안에서만 읽으며 저장·외부 전송·AI 호출은 하지 않습니다.

## AI 없이 원문에서 활용할 수 있는 단서

| 단서 | 만들 수 있는 제안 | 이번 시안 |
|---|---|---|
| 글자·어절·문장의 길이, 빈 줄 | 이어 쓰는 속도와 쪽 나눔 | 적용 |
| 마침표·쉼표·말줄임표·두 칸 이상의 공백 | 멈추는 시간과 여운 | 적용 |
| 짧고 독립적인 문장 | 느린 호흡과 강조 후보 | 호흡 적용, 후보는 사용자가 채택 |
| 같은 형태로 반복되는 낱말 | 반복의 리듬을 살릴 위치 | 빈도 제시; 활용형을 같은 어근으로 묶는 분석은 미구현 |
| 하지만·그런데·그러다 같은 전환 표현 | 반전 위치 후보 | 제안만 하고 사용자가 선택 |
| 밤·어둠·새벽 같은 낱말 | 밝거나 어두운 바탕 후보 | 제안만 하고 사용자가 선택 |
| 따옴표와 직접 인용 | 대사나 인용 전후의 간격 | 따옴표 문장 집계와 부호 보존; 화자 구분은 미구현 |
| 의문·명령·평서형 어미 | 문장 끝의 호흡 차이 | 문장부호 규칙만 구현; 어미 분석은 후속 후보 |
| 시간·장소 표현의 바뀜 | 장면 전환 후보 | 후속 후보 |

단어 사전과 문법 규칙만으로 감정, 반어, 사건의 중요도를 확정할 수는 없습니다. ‘하지만’이 나왔다고 반드시 반전인 것도 아니므로 관찰된 단서를 보여 주고 고르게 합니다. 사용자가 고른 위치를 우선합니다. 낱말마다 장식을 덧붙이기보다 바탕·속도·호흡의 후보를 만드는 근거로 활용합니다.

## 심상 조합의 역할

분위기는 제각각의 효과 버튼이 아니라 일관된 표현 조합으로 연결합니다.

- 따뜻한 + 고요한: 온기 있는 종이, 부드러운 빛, 조금 느린 흐름과 긴 쉼.
- 서늘한 + 팽팽한: 회청색 바탕, 또렷한 등장, 조금 짧고 빠른 호흡.
- 따뜻한 + 아련한: 따뜻한 바탕, 천천히 또렷해지는 글자, 문장 끝의 여유.

시안에서는 색온도, 진행 속도, 쉼 배율을 조합합니다. 분위기만으로 본문의 뜻을 추정하거나 문장을 다시 쓰지 않습니다. 지정한 전환 위치에서는 새 쪽과 낮밤 전환을 첫 안으로 제시하며, 결과에서 쪽별 낮밤을 바꿀 수 있습니다.

## 열어 보기

[`downloads/geulgyeol-first-draft.html`](../downloads/geulgyeol-first-draft.html) 하나에 화면, 코드, 예시 글과 글꼴을 포함했습니다. 별도 설치나 서버가 필요 없습니다. 파일을 내려받아 브라우저에서 엽니다. 앱이 HTML을 소스 보기로 여는 경우에도 내려받은 파일을 브라우저에서 열 수 있습니다.

1. 상단 PC·모바일 버튼으로 화면 폭을 바꿉니다. 작성 중인 글과 선택은 유지됩니다.
2. ‘예시 글 넣기’를 누르거나 글을 입력합니다. 기존 글이 있으면 예시가 덮어쓰지 않습니다.
3. 분위기를 고르고, 필요하면 강조 문장과 전환 지점을 고릅니다.
4. ‘첫 안 보기’에서 움직임과 쪽 흐름을 확인합니다.
5. ‘다듬기’에서 낮밤, 등장 방식, 속도, 쉼을 바꾸고 제안을 선택합니다.

현재 문서는 디자인·규칙 기반 초안 생성의 프로토타입입니다. 발행 기능, 기존 GeulFx/GeulBackdrop 엔진 통합, 저장소의 블록 문법 편집 기능은 포함하지 않았습니다. 예시는 저장소의 공개 예시 글을 사용했습니다. 입력한 글은 새로고침하거나 파일을 닫으면 유지되지 않습니다.

## 검증

- 분석 규칙 10개 테스트 통과: 빈 줄, 위치 보존, 명시적 반전·강조, 공백의 쉼, 긴 글과 이모지 보존, 후보와 자동 적용의 구분, 분위기·속도 반영 등.
- 완성 HTML을 Chromium에서 네트워크가 끊긴 상태로 실행하여 입력부터 다듬기까지 확인했습니다.
- PC·모바일 전환, 실제 390px 너비, 키보드 닫기, 움직임 줄이기, 원문 수정 후 선택 초기화, 예시 덮어쓰기 방지, HTML 문자열 안전 표시를 확인했습니다.
- 검사 중 외부 HTTP 요청과 JavaScript 오류는 없었습니다. CSP도 외부 연결을 허용하지 않습니다.
- 클라우드 Chromium은 관리 정책상 file URL 직접 탐색을 차단하므로, 동일한 독립 HTML 내용을 오프라인 문서로 로드하여 검증했습니다. GitHub Pages에서는 분리된 정적 파일로 실행합니다.

기존 저장소 파일은 변경하지 않았습니다.
