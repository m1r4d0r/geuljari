# 글자리 단계 계획

최신 정리: 2026-10-11 (한국 시간). 사용자 확정 기준은 [README](../README.md), 발행 상세는 [발행](발행.md)을 따른다. 과거 시안의 번호나 제안은 완료 여부의 근거로 쓰지 않는다.

## 기본 방향

**가능한 한 Netlify 안에서 구현한다.** 정적 사이트 + Netlify Functions + **Netlify Blobs**가 목표 구성이다. Firebase/Firestore나 별도 DB·인증·알림 서비스를 필수로 붙이지 않는다. 향후 문의·관리도 Netlify 내 구현부터 검토한다. 외부 서비스는 내부 대안으로 충족하기 어려운 요구가 있을 때 필요성을 설명해 별도 선택 사항으로 다룬다.

## 현재 상태

| 영역 | 확인한 상태 | 다음 일 |
| --- | --- | --- |

## 1. 지금 할 일 — Blobs 전환

1. `server/store.mjs`를 Blobs 어댑터로 교체하고 `firebase-admin`, Firebase 환경 변수 의존을 제거한다.
2. 문서 단위 저장과 버전 확인을 설계한다. 생성 중복 방지, 동시 수정 거부, 수정·삭제 경합에서 삭제한 글이 되살아나지 않는 동작을 보존한다. Firestore 트랜잭션을 단순 get/set으로 치환하지 않는다.
3. 발행 중단 직후 새 읽기 요청이 거절되도록 저장소 읽기 일관성과 캐시 정책을 함께 확인한다.
4. 재배포에도 남는 운영 저장소를 사용하고, 브랜치 미리보기·로컬 검증 데이터는 운영과 분리한다.
5. API·브라우저 검증을 Blobs 어댑터 기준으로 갱신한 뒤 실제 Netlify 미리보기에서 저장·읽기·중단·삭제·재배포 후 보존을 확인한다.
6. 완료 후 [발행](발행.md), README, CLAUDE.md의 ‘전환 전’ 상태를 실제 결과로 갱신한다.

완료 조건: Firebase 없이 Netlify 안에서 발행하고, 같은 `/t/{id}#{열쇠}` 주소로 수정·재발행하며, 최신 버전 보호·환경 분리·저장 보존이 확인돼야 한다.

## 2. 기존 화면과 통합

- 헤더: 편집 · 미리보기 · 발행. 오른쪽 여백 색인은 설정에만 사용한다.
- 색인을 열면 아래 항목이 밀리고 한 번에 하나만 열린다. 미리보기 도구는 하단바에 둔다.
- 최신 main의 브랜딩·바탕 변경과 이 브랜치의 발행·색인을 합칠 때 기존 파일 ID, 장면 이름, 조판값 호환성을 확인한다.
- 현재는 별도 브랜치 지시가 유효하다. 문서 정리나 저장소 전환을 main 병합·운영 배포 승인으로 해석하지 않는다.

## 3. 후속 기능 — 아직 미구현 또는 정책 미정

- OG 이미지: 공개 제목 중심. ‘글의 결’ 메타를 공개할지와 기본값은 미정. 현재는 공개 제목 OG HTML만 구현했다.
- 문의·관리실: Netlify Functions와 Blobs 안에서 가능한 범위를 먼저 설계한다. Discord 웹훅·이메일·외부 로그인은 기본 필수가 아니다. 관리자 인증과 문의 답장 전달 방식은 미정이다.
- 소리: 브라우저 Web Audio로 가능한 효과부터 검토한다. 현재 구현 완료로 표시하지 않는다.
- 운영 정책: 글 수·크기·만료, 신고·삭제, 비용 상한과 사용량 관찰, 백업·복구를 정한다. Blobs 선택만으로 무제한·무료 운영을 보장하지 않는다.
- 비밀번호 분실: 현재 구현에는 재설정·복구가 없다. 운영자의 게시 중단 지원 등 별도 정책은 아직 확정하지 않았다.

## 검증 기준

- 개인 글 대신 저장소의 예시 글만 사용한다.
- 문서 수정은 상충 내용·상태 구분·링크를 확인한다. 실행 코드를 고칠 때 관련 구문·기능 검증을 진행한다.
- 로컬 메모리 저장소에서 통과한 결과와 실제 Netlify/Blobs 확인 결과를 구분해 기록한다.
