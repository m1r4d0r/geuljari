# 글자리 /t/ 발행 — Netlify 내부 구현

최신 결정: **2026-10-12 (한국 시간)**. 사용자 목표는 가능한 한 여러 서비스를 연결하지 않고 **Netlify 안에서 구현하는 것**이다. 현재 확정 구성은 **Netlify 정적 호스팅 + Netlify Functions + Netlify Blobs**다.

## 사용 흐름

헤더의 **편집 → 미리보기 → 발행**에서 공개 제목, 작성자 비밀번호(4~128자, 그 밖의 제약·잠금 없음, 한 번 입력), 발행 여부를 정한다. 전체 링크는 `/t/{id}#{열쇠}`다. 같은 글을 수정해 저장하면 주소가 유지된다. 독자는 비밀번호 없이 전체 링크로 읽는다.

발행 뒤 '링크와 비밀번호 남겨 두기'에서 **보내기**(Web Share: 폰 공유 창, 카카오톡 나와의 채팅 등. 공유 창이 없는 브라우저에서는 단추를 숨김), **텍스트 복사**(제목·링크·비밀번호 세 줄), **글 파일 받기**(`[발행] 제목 발행한 날.txt`, 링크·비밀번호 포함)를 고른다. 따로 된 관리 파일은 없다. 비밀번호는 메모리에만 있으므로 링크·비밀번호가 든 글 파일은 발행 직후나 불러온 동안에만 받을 수 있고, 그 밖에는 `[초안] 제목 날짜.txt`가 된다. **불러오기**에서 링크와 비밀번호를 입력하거나 글 파일을 선택·드롭한다. 링크·비밀번호가 든 글 파일이면 파일의 본문을 그대로 두고 발행 글과 다시 잇는다. 예전 관리 파일(줄글·JSON)은 링크·비밀번호 칸을 채운다. 불러온 뒤 상단 띠의 **발행 관리**에서 수정, 발행 중단, 재발행, 삭제를 한다. 삭제해도 편집창 초안은 남는다. 새로 쓰기는 기존 발행 글과의 연결을 끊는다.

뷰어의 **작성자 수정**을 누르면 `/#edit={id}.{key}`의 fragment로 전체 링크를 편집실에 전달한다. 편집실은 주소에서 fragment를 지우고 비밀번호 확인 창을 연다. 비밀번호를 API에서 검증하고 본문 열쇠로 복호화한 뒤에만 불러오며, 기존 초안이 있으면 교체를 확인한다. 비공개 상태에서도 같은 링크에서 이 진입점을 제공한다. 비밀번호와 열쇠는 localStorage에 저장하지 않는다.

발행 전에는 전체 링크의 읽기 권한, 작성자 비밀번호의 관리 권한, 분실 시 복구 불가를 안내한다. 발행 중단 뒤에도 독자의 사본은 회수되지 않는다는 안내도 유지한다.

### 끝 장 카드 편집

미리보기 쪽 눈금 끝의 테두리 네모로 이동한다. 문구 기본값은 편집 제목(없으면 첫 문장)이며 카드에서 바로 고쳐 별도 문구 120자까지 둘 수 있다. 문구는 엔터로 네 줄까지 나눈다. 하단바 ‘글’ 갈래의 ‘편집 제목으로’를 누르면 제목 연동으로 돌아간다. 같은 갈래에서 카드 글꼴(이 카드만, 기본은 본문 글꼴), 글자 크기 28~120px, 문구 폭 30~90%, 왼쪽·가운데·오른쪽 정렬을 고른다. 위치(가로·세로 0~100%)는 카드의 ‘위치 이동’을 끌거나(가로·세로 가운데에 붙음) 방향키로 옮기며 카드 안전 영역 안에서 움직인다. 긴 문구는 카드 안에서 줄임표로 표시한다.

카드 문구를 바꿔도 편집 제목과 공개 제목은 바뀌지 않는다. 값은 `ending.text/font/size/width/x/y/align`에 저장하고 본문과 함께 암호화한다. 기본 바탕 값 `scene/ground`도 유지한다. 카드 아래 날짜 안내는 제거했고, 미리보기의 ‘이대로 발행하기’는 발행 단계로 이동한다. 카드 안의 작은 날짜 표기는 유지한다.

### 공유 이미지 자동 생성

발행·공개 상태 수정 때 끝 장 카드를 **1200×630 PNG**로 만든다. 별도 같은 출처 프레임에서 발행 시점의 문구·줄바꿈·글꼴·크기·폭·위치·정렬·장면·바탕·주색을 읽어 `GeulEnding.exportCard()`로 그린다. 화면용 카드와 같은 그리기 코드를 쓰며 로고와 카드 안 날짜도 유지한다. 미리보기를 열지 않았거나 닫은 뒤에도 생성한다. 글 자료는 프레임 주소·저장소·외부 이미지 서비스로 보내지 않는다.

PNG는 공개 자료다. **제목과 이미지에 그려진 문구는 링크 미리보기에 공개**된다고 발행 화면에 안내한다. 끝 장 설정 원본과 본문은 계속 암호화하고, 이미지에 문구를 그리기 위해 서버에서 본문을 복호화하지 않는다. 문구 기본값이 제목 또는 첫 문장이므로 카드에 공개할 문구를 확인할 수 있다.

이미지는 base64 `ogImage`, 내용 해시 `ogHash`로 본문과 **같은 Blobs 문서에 한 번의 조건부 쓰기**로 저장한다. 이미지와 본문 중 하나만 갱신되는 상태를 만들지 않는다. PNG는 최대 2,000,000바이트, JSON 요청은 최대 3,100,000바이트이며 기존 암호문 제한 350,000자는 유지한다. 서버는 PNG 서명·1200×630 크기·청크 체크섬·압축 해제 크기를 확인한다. 일반 본문 조회·비밀번호 확인 응답에는 이미지 바이트를 넣지 않는다.

`/t/{id}`의 서버 HTML에 `/og/{id}/{내용해시}.png`의 절대 주소와 크기·형식, Twitter 큰 이미지 태그를 넣는다. 크롤러는 자바스크립트나 `#` 열쇠 없이 이미지를 읽는다. 이미지가 바뀌면 주소도 바뀌고 이전 주소는 404가 된다. 공개 이미지 GET/HEAD는 매번 게시 상태를 확인하고 브라우저·Netlify CDN에 `no-store`를 보낸다. 발행 중단·삭제 후에는 HTML에서 이미지 태그를 빼고 이미지도 404로 응답한다. 이미 외부 서비스가 복사한 공유 미리보기는 회수할 수 없으며 해당 서비스의 캐시 갱신이 필요할 수 있다.

이미지 생성이 실패하면 공개 발행을 완료했다고 표시하지 않는다. 응답 유실 후 재시도는 같은 PNG·암호문을 재사용한다. 발행 중단은 이미지 생성 없이 처리해 글꼴·그림 오류로 중단이 막히지 않는다. 구형 클라이언트가 이미지 필드 없이 수정하면 기존 그림을 보존한다. 이미지가 없는 기존 글은 작성자가 불러와 공개 상태로 다시 저장할 때 생성한다.

현재 비밀번호 재설정·분실 복구는 없다. 이미 독자가 받은 사본은 중단·삭제로 회수되지 않는다. 다른 창에서 먼저 수정하면 덮어쓰기를 거부하고 편집 중인 내용은 남긴다.

## Netlify 안에서 맡길 역할

- **정적 호스팅:** 편집실과 읽기 엔진의 HTML/CSS/JS. 프런트엔드는 번들하지 않는다. `npm run build`는 배포 컨텍스트 설정을 생성하고 공개 파일만 `dist/`에 복사한다.
- **Functions:** 생성·읽기·비밀번호 확인·수정·중단·삭제 API, `/t/` 공유 메타 HTML, `/og/` 공개 PNG. 기존 `netlify/functions/` 진입점과 사용자 흐름을 유지한다.
- **Blobs:** 암호문과 공개 제목·카드 PNG, 비밀번호 해시, 게시 상태, 날짜, 버전을 저장한다. 브라우저가 저장소에 직접 쓰지 않고 Functions가 인증·입력 검증 뒤 접근한다.
- **외부 서비스:** 별도 DB·로그인·알림 서비스는 기본 구성에 넣지 않는다. 문의·관리 기능도 Netlify 안에서 우선 설계한다. 외부 연동은 꼭 필요한 경우에만 내부 대안과 비교해 별도 선택 사항으로 다룬다.

## Blobs 구현

- `server/store.mjs`가 API의 `get`·`change` 경계를 구현한다. 문서에는 `id, title, cipher, iv, ogImage, ogHash, salt, passwordHash, live, createdAt, updatedAt, revision`을 저장한다.
- 최초 생성은 `onlyIfNew`로 기존 주소 덮어쓰기를 막는다. 동일 생성 요청의 재시도는 기존 암호문·비밀번호가 일치할 때 같은 글을 돌려준다. 생성 재시도도 기존 비밀번호를 실제로 검증한다.
- 수정은 강한 일관성으로 읽은 ETag에 `onlyIfMatch`를 걸어 저장한다. 사용자 `revision`과 저장소 조건 중 하나라도 맞지 않으면 409다. ETag가 없으면 조건 없는 저장으로 우회하지 않는다. 수정 응답이 유실되면 클라이언트가 같은 암호문·IV·기준 버전으로 재시도한다. 서버의 버전이 정확히 하나 앞서고 내용이 같은 경우에는 저장 완료로 돌려주며 추가 버전을 만들지 않는다. 다른 내용이거나 더 오래된 버전은 409다.
- 삭제는 같은 조건으로 `{id, deleted:true}`만 남긴다. 본문 암호문·제목·카드 이미지·비밀번호 해시는 제거하며 ID를 예약해 지연된 수정이나 재생성이 글을 되살리지 못하게 한다. 삭제 응답 유실 뒤 같은 요청을 다시 보내면, 이미 없는 글은 삭제 완료로 돌려준다.
- 중단·삭제 상태는 강한 일관성 읽기로 확인한다. API, `/t/`, `/og/` 응답은 `no-store`다.

### 저장소와 배포 컨텍스트

`scripts/deploy-config.mjs`가 빌드 환경을 검증하고 `scripts/build.mjs`가 `server/deploy-config.json`을 생성한다. 함수 번들에 이 설정을 포함하므로 함수 실행 시 빌드 전용 환경 변수에 의존하지 않는다.

| 컨텍스트 | 저장소 |
| --- | --- |
| production | `geuljari-articles-v1` — 같은 사이트의 재배포에도 유지 |
| deploy-preview / branch-deploy / Netlify dev | `geuljari-preview-{DEPLOY_ID}` — 배포마다 분리 |
| Netlify 밖 로컬 dev | `geuljari-local-v1` |

알 수 없는 Netlify 컨텍스트나 없는 배포 ID는 빌드를 실패시킨다. 브라우저 요청으로 저장소를 고를 수 없다. 미리보기 재배포는 새 저장소를 사용하므로 이전 미리보기 글이 새 배포에 이어지지 않는다. 이 이름 분리는 애플리케이션의 자료 혼용을 막는 용도이며, 같은 사이트의 신뢰된 함수 코드 사이의 권한 격리는 아니다.

공식 참고: [Netlify Blobs](https://docs.netlify.com/build/data-and-storage/netlify-blobs/). 별도 데이터베이스 계정이나 Firebase 설정 없이 Netlify가 제공하는 함수 실행 컨텍스트로 연결한다. 복잡한 목록·검색·집계는 후속 요구에 맞춰 별도 설계한다.

## 암호화와 공개 범위 — 현재 구현에서 유지

- 본문·조판값·분위기·날짜·끝 장 설정은 브라우저 WebCrypto AES-GCM 256으로 암호화한다. IV는 매번 12바이트 난수, 열쇠는 32바이트 난수다. AAD에 형식 버전과 ID를 묶는다.
- 본문 열쇠는 URL의 `#` 뒤에만 두고 API에 보내지 않는다. 공개 제목은 서버와 OG HTML에 평문으로 남고 끝 장 PNG는 공개 이미지로 저장한다. HTML에는 본문·열쇠·비밀번호를 넣지 않는다. 이미지에 그린 문구는 공개 범위에 포함된다.
- 수정 비밀번호는 HTTPS API에 전송하며 서버에는 무작위 salt + scrypt(N=32768, r=8, p=1) 해시를 저장한다. 응답에는 salt/해시를 노출하지 않는다.
- 비공개·삭제 글은 공개 API에서 404. 요청 크기·필드 길이·메서드·Origin 확인과 함수별 요청 제한을 유지한다.
- 편집실의 기존 초안은 브라우저 localStorage에 평문으로 보관한다. localStorage는 주소(origin)마다 따로라서 주소가 바뀌면 초안이 보이지 않는다. 헤더의 **글 파일 받기**로 받은 `.txt`(제목·처음 쓴 날, 표시가 든 본문, 글 전체 설정을 `이름: 값` 줄로)를 **불러오기**에 놓으면 그대로 돌아온다. 글 파일은 서버로 보내지 않는다(`geul-file.js`). 비밀번호·본문 열쇠는 localStorage에 넣지 않는다. 새로고침 뒤에는 다시 불러와야 발행 글을 관리할 수 있다.
- 공개 읽기 화면은 편집실의 저장 자료를 읽지 않는다. 열쇠가 없거나 틀리면 예시 글 대신 오류를 보여 준다.
- 문의·관리자 화면, 비밀번호 복구, 만료·신고 정책은 이번 발행 구현에 포함되지 않았다.

## 사용자가 Netlify에서 설정할 것

현재 운영 사이트 `https://geuljari.netlify.app`에서 Functions 경로와 Blobs 읽기·쓰기가 동작한다. **추가 환경 변수·API 키·Firebase 계정·Blobs 저장소 수동 생성은 필요 없다.** Functions 실행 시 Netlify가 사이트와 저장소 인증 정보를 제공하며 저장소는 처음 쓰면서 만들어진다. `NETLIFY_BLOBS_CONTEXT`나 개인 토큰을 수동으로 등록하지 않는다.

배포 설정은 저장소 `netlify.toml`에 있다: 빌드 `npm run build`, 공개 폴더 `dist`, Functions `netlify/functions`, Node 22. 이미 연결된 GitHub 저장소와 같은 Netlify 프로젝트를 유지한다. 새 프로젝트로 옮기는 작업은 데이터 이전과 별개다.

2026-10-11 운영 검증은 기존 배포 코드로 예시 글 한 편을 만들어 수행했다. 발행, 암호문 조회·복호화, `/t/` 제목 HTML, 잘못된/올바른 비밀번호, 같은 주소 수정, 중단 후 본문·제목 접근 차단, 재발행, 삭제를 확인했다. 검증 글은 마지막에 삭제했다. 재배포 후 보존은 저장소 설계 및 로컬 검증으로 확인한 상태이며 이번 운영 검증에서 배포를 새로 실행하지는 않았다.

발행 전용 브랜치의 추가 수정은 생성·수정·삭제 응답 유실 후 재시도, 발행 서버 응답 형식 확인, 글 파일의 열쇠 복호화 확인이다. OG 이미지 자동 생성·Blobs 저장·공개 경로도 구현했다. 편집실에는 스크립트 연결과 공개 범위 안내만 추가했다. 메뉴·레이아웃 작업과 분리해 별도 병합 전까지 운영에 반영하지 않는다.

## 운영 배포·확인

1. 통합 코드와 검증 결과를 main에 반영한다. Netlify 연결 저장소가 `m1r4d0r/geuljari`, 운영 브랜치가 `main`인지 확인한다.
2. `netlify.toml`의 `npm run build`, 공개 디렉터리 `dist`, 함수 디렉터리 `netlify/functions`, Node 22 설정으로 배포한다. 별도 Firebase 환경 변수는 사용하지 않는다.
3. 함수 변경을 배포한 뒤 실제 Netlify에서 발행·읽기·수정·중단·재발행·삭제를 확인한다. 기존 운영 검증과 새 변경의 로컬 검증은 구분한다.
4. 운영 글의 재배포 후 보존과 미리보기 분리를 확인한다. 사용량·백업·복구 정책은 후속 운영 과제로 남긴다.

Netlify 사이트 주소만 바꿀 때도 기존 사이트의 저장소 연결과 ID·열쇠를 보존하는지 확인한다. 새 Netlify 프로젝트를 만들면 데이터 이전이 별도 필요할 수 있다. 옛 링크 유지에는 기존 주소 유지나 리다이렉트가 필요하며 `#` 열쇠 보존도 확인한다.

- `netlify/functions/`: 실제 함수 진입점. `netlify.toml`: 공개 파일과 함수 배포 설정.

```sh
npm ci
npm test
npm run build
# Playwright가 설치된 검증 환경에서:
CHROMIUM=/path/to/chromium npm run test:publish-ui
```

확인한 범위:

- `npm test`: API 검증과 실제 SDK 조건부 쓰기, 수정·삭제 경합, 삭제 후 주소 재사용 금지, 로컬 서버 재시작 후 보존, 운영·미리보기 저장소 분리.
- `npm run test:publish-ui`: 공식 로컬 Blobs 서버를 연결한 발행·복호화·잘못된 열쇠·중단·잘못된 비밀번호·텍스트 복사·발행/초안 글 파일 받기·글 파일로 다시 잇기·예전 관리 파일(줄글·JSON)·불러오기·재발행·충돌·삭제와 모바일 UI.
- OG 검증: PNG 형식·손상·크기·압축 폭탄 거부, HTML 메타·공개 이미지·HEAD·구형 자료 호환, 이미지 갱신·중단·삭제·응답 유실. 브라우저는 화면 카드와 PNG 일치, 문구·배치·바탕·주색 반영, 모바일에서도 1200×630, 생성 실패 후 재시도를 확인한다. 글꼴 CDN 요청을 차단한 로컬 검증은 대체 글꼴 기준이다.
- 미리보기 하단바·고치기: 1440/390px(`tune-bar.cjs`), 편집 하단바·카드: 1280/768/390/320px 및 가로 화면(`studio-refinement.cjs`). 읽기: PC·모바일, 끝 장·다시 읽기.
- `CHROMIUM=/path/to/chromium node tests/smoke_brand_effects.cjs`: PC·모바일 로고, 원고지·타자 렌더, 넘김 11종. 함수 esbuild 번들도 확인했다.

**로컬 서버 제한:** SDK 11.1.4의 로컬 `BlobsServer`는 읽기 응답에 ETag를 주지 않아 테스트 fixture에서 목록 응답의 ETag를 보충한다. 조건부 쓰기는 공식 SDK·서버로 실행한다. 운영 어댑터에는 이 우회가 없으며 ETag 없는 수정은 실패한다. 이 검증은 실제 Netlify 플랫폼의 권한·캐시·재배포 확인을 대체하지 않는다. 테스트 서버·보충 코드는 배포 함수에 포함하지 않는다.

`tests/studio-refinement.cjs`는 1280/768/390/320px·가로 화면에서 서랍, 카드 문구·배치 저장, 재열기, 발행 연결, 뷰어 작성자 진입·비밀번호 실패/성공·중단 후 관리 진입을 확인한다.
