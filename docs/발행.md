# 글자리 /t/ 발행 — Netlify 내부 구현

최신 결정: **2026-10-11 (한국 시간)**. 사용자 목표는 가능한 한 여러 서비스를 연결하지 않고 **Netlify 안에서 구현하는 것**이다. 현재 확정 구성은 **Netlify 정적 호스팅 + Netlify Functions + Netlify Blobs**다.

## 목표와 현재 코드 상태

| 항목 | 현재 상태 |
| --- | --- |
| 발행·불러오기·관리 UI | 별도 브랜치 `codex/geuljari-margin-index`에 구현 |
| 브라우저 암호화, `/t/` 읽기, 제목 OG HTML | 같은 브랜치에 구현 |
| 로컬 API·브라우저 검증 | 메모리 저장소를 주입해 통과 |
| Blobs 저장소 | **계획 확정, 코드 전환 전** |
| 현재 저장소 어댑터 | `server/store.mjs`의 Firestore 구현과 `firebase-admin`이 남아 있음. 제거·교체 대상 |
| 실제 Netlify 발행 | 통합 검증·운영 배포 미완료 |

Firestore는 과거 README P-22의 미확정 아이디어를 구현에 잘못 적용한 것이다. **Firebase 프로젝트 생성이나 서비스 계정 설정은 진행하지 않는다.** 이 문서의 Blobs 계획을 이미 구현된 동작으로 보고하지 않는다. 본 문서 갱신은 Markdown 정리이며 제품 코드를 바꾸지 않았다.

## 사용 흐름 — 유지할 부분

헤더의 **편집 → 미리보기 → 발행**에서 공개 제목, 수정용 비밀번호(현재 UI 8~128자), 발행 여부를 정한다. 전체 링크는 `/t/{id}#{열쇠}`다. 같은 글을 수정해 저장하면 주소가 유지된다. 독자는 비밀번호 없이 전체 링크로 읽는다.

발행 뒤 링크를 복사하거나 관리 파일을 내려받는다. 관리 파일에는 전체 링크와 비밀번호가 들어 있다. **불러오기**에서 링크와 비밀번호를 입력하거나 파일을 선택·드롭한다. 불러온 뒤 상단 띠의 **발행 관리**에서 수정, 발행 중단, 재발행, 삭제를 한다. 삭제해도 편집창 초안은 남는다. 예시 글과 새로 쓰기는 기존 발행 글과의 연결을 끊는다.

현재 비밀번호 재설정·분실 복구는 없다. 이미 독자가 받은 사본은 중단·삭제로 회수되지 않는다. 다른 창에서 먼저 수정하면 덮어쓰기를 거부하고 편집 중인 내용은 남긴다.

## Netlify 안에서 맡길 역할

- **정적 호스팅:** 편집실과 읽기 엔진의 HTML/CSS/JS. 프런트엔드는 번들하지 않는다. 현재 `npm run build`는 공개 파일만 `dist/`에 복사한다.
- **Functions:** 생성·읽기·비밀번호 확인·수정·중단·삭제 API와 `/t/` 제목 메타 HTML. 기존 `netlify/functions/` 진입점과 사용자 흐름을 유지한다.
- **Blobs:** 암호문과 공개 제목, 비밀번호 해시, 게시 상태, 날짜, 버전을 저장한다. 브라우저가 저장소에 직접 쓰지 않고 Functions가 인증·입력 검증 뒤 접근한다.
- **외부 서비스:** 별도 DB·로그인·알림 서비스는 기본 구성에 넣지 않는다. 문의·관리 기능도 Netlify 안에서 우선 설계한다. 외부 연동은 꼭 필요한 경우에만 내부 대안과 비교해 별도 선택 사항으로 다룬다.

## Blobs 전환 설계와 확인할 점

아래는 **후속 구현 과제**다. 자세한 SDK 호출·삭제 방식은 전환 작업에서 검증한다.

1. `server/store.mjs`의 저장소 경계를 유지해 Firestore를 Blobs로 교체한다. `package.json`·잠금 파일의 Firebase 의존을 제거하고 필요한 Netlify SDK로 바꾼다.
2. 문서별로 `id, title, cipher, iv, salt, passwordHash, live, createdAt, updatedAt, revision`을 보관한다. `revision`은 사용자에게 충돌을 알리는 버전 값이다. 실제 동시 쓰기 보호는 Blobs의 조건부 쓰기와 저장소 버전 확인을 함께 설계한다.
3. 최초 생성은 이미 존재하는 주소를 덮어쓰지 않는다. 생성 응답이 유실돼 같은 요청을 재시도해도 중복 글을 만들지 않는다.
4. 수정은 읽었던 버전과 현재 저장된 버전이 일치할 때만 반영한다. 단순 get/set은 쓰지 않는다. 조건이 맞지 않으면 기존 409 충돌 안내를 유지한다.
5. 삭제는 수정과 경합해도 삭제한 글이 되살아나지 않도록 설계한다. 필요하면 삭제 표식을 조건부로 기록하는 방식을 검토하고, 암호문 제거·표식 보존 범위를 정한다. API만 바꾸고 Firestore 트랜잭션과 같다고 가정하지 않는다.
6. 발행 중단 직후 이후 읽기 요청에 상태가 반영되도록 일관성을 설정한다. API와 `/t/` HTML의 `no-store` 정책도 유지한다.
7. 운영 글은 재배포 후에도 유지돼야 한다. 배포별 임시 저장소를 운영 저장소로 쓰지 않는다. 미리보기와 운영의 네임스페이스·접근 경계를 명확히 분리하고 미리보기의 수정·삭제가 운영 자료에 닿지 않는지 확인한다.
8. 향후 목록·검색·집계·카운터를 붙일 때 Blobs 전체 열거와 쓰기 경합 비용을 별도 검토한다. 복잡한 DB 동작이 자동으로 제공된다고 전제하지 않는다.

공식 참고: [Netlify Blobs](https://docs.netlify.com/build/data-and-storage/netlify-blobs/) — 저장소 수명, 조건부 쓰기, 읽기 일관성, 배포 범위. SDK 사용법·요금·제한은 구현 시점에 다시 확인한다.

## 암호화와 공개 범위 — 현재 구현에서 유지

- 본문·조판값·분위기·날짜·끝 장 설정은 브라우저 WebCrypto AES-GCM 256으로 암호화한다. IV는 매번 12바이트 난수, 열쇠는 32바이트 난수다. AAD에 형식 버전과 ID를 묶는다.
- 본문 열쇠는 URL의 `#` 뒤에만 두고 API에 보내지 않는다. 공개 제목은 서버와 OG HTML에 평문으로 남는다. OG에는 본문이나 열쇠를 넣지 않는다.
- 수정 비밀번호는 HTTPS API에 전송하며 서버에는 무작위 salt + scrypt(N=32768, r=8, p=1) 해시를 저장한다. 응답에는 salt/해시를 노출하지 않는다.
- 비공개·삭제 글은 공개 API에서 404. 요청 크기·필드 길이·메서드·Origin 확인과 함수별 요청 제한을 유지한다.
- 편집실의 기존 초안은 브라우저 localStorage에 평문으로 보관한다. 비밀번호·본문 열쇠는 localStorage에 넣지 않는다. 새로고침 뒤에는 다시 불러와야 발행 글을 관리할 수 있다.
- 공개 읽기 화면은 편집실의 저장 자료를 읽지 않는다. 열쇠가 없거나 틀리면 예시 글 대신 오류를 보여 준다.
- OG 이미지, 문의·관리자 화면, 비밀번호 복구, 만료·신고 정책은 이번 발행 구현에 포함되지 않았다.

## 전환 뒤 배포·확인 순서

1. 같은 별도 브랜치에서 Blobs 어댑터와 충돌·삭제 보호를 구현하고 관련 API·브라우저 검증을 갱신한다.
2. Netlify 미리보기에서 Functions와 격리된 Blobs 저장소를 연결한다. 사이트·배포 컨텍스트를 확인하고 별도 Firebase 자격 증명은 추가하지 않는다.
3. 예시 글로 발행, 다른 브라우저 읽기, 불러오기, 수정 충돌, 중단 직후 읽기, 재발행, 삭제 경합을 확인한다.
4. 재배포 후 글이 남는지, 미리보기와 운영 자료가 섞이지 않는지 확인한다. 사용량·백업·복구 방식을 정리한다.
5. 현재 별도 브랜치 지시를 유지한다. main 통합·운영 배포 시점은 병렬 작업 종료에 관한 사용자 지시에 따른다.

Netlify 사이트 주소만 바꿀 때도 기존 사이트의 저장소 연결과 ID·열쇠를 보존하는지 확인한다. 새 Netlify 프로젝트를 만들면 데이터 이전이 별도 필요할 수 있다. 옛 링크 유지에는 기존 주소 유지나 리다이렉트가 필요하며 `#` 열쇠 보존도 확인한다.

## 파일과 검증 명령

- `publish.js/css`, `publish-crypto.js`: 발행·불러오기·암호화.
- `published.html/js/css`, `reader.js`: 공개 읽기 틀.
- `server/articles.mjs`, `server/store.mjs`, `server/reader-page.mjs`: API·저장소 어댑터·공개 제목 HTML.
- `netlify/functions/`: 실제 함수 진입점. `netlify.toml`: 공개 파일과 함수 배포 설정.

```sh
npm ci
npm test
npm run build
# Playwright가 설치된 검증 환경에서:
CHROMIUM=/path/to/chromium npm run test:publish-ui
python3 tests/smoke_margin_index.py /tmp/geulteul-margin-check
```

기존 검증은 예시 글로 발행·복호화·잘못된 열쇠·중단·잘못된 비밀번호·관리 파일·재발행·충돌·삭제와 1280/390/320px 레이아웃을 확인했다. 여백 색인은 네 화면 크기에서 확인했다. **현재 발행 테스트의 저장소는 메모리이므로 Blobs 연동 검증을 대체하지 않는다.** 테스트 저장소는 배포 함수에 포함하지 않는다.
