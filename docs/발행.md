# 글자리 /t/ 발행 — Netlify 내부 구현

최신 결정: **2026-10-11 (한국 시간)**. 사용자 목표는 가능한 한 여러 서비스를 연결하지 않고 **Netlify 안에서 구현하는 것**이다. 현재 확정 구성은 **Netlify 정적 호스팅 + Netlify Functions + Netlify Blobs**다.

## 목표와 현재 코드 상태

최신 main `bdcf818`의 글자리 로고·원고지·타자 바탕과 여백 색인·발행 기능을 통합했다. 2026-10-11 사용자가 main 병합과 운영 배포를 승인했다.

| 항목 | 현재 상태 |
| --- | --- |
| 발행·불러오기·관리 UI | 구현, 헤더 단계 이동에 연결 |
| 브라우저 암호화, `/t/` 읽기, 제목 OG HTML | 구현 |
| Blobs 저장소 | `@netlify/blobs` 11.1.4로 전환 완료 |
| Firebase | 어댑터·의존성 제거, 별도 프로젝트·서비스 계정 불필요 |
| 로컬 API·브라우저 검증 | 공식 로컬 Blobs 서버와 SDK로 통과 |
| 실제 Netlify 발행 | main 반영 후 운영 배포·접근 확인 필요 |

## 사용 흐름

헤더의 **편집 → 미리보기 → 발행**에서 공개 제목, 작성자 비밀번호(현재 UI 8~128자), 발행 여부를 정한다. 전체 링크는 `/t/{id}#{열쇠}`다. 같은 글을 수정해 저장하면 주소가 유지된다. 독자는 비밀번호 없이 전체 링크로 읽는다.

발행 뒤 링크를 복사하거나 관리 파일을 내려받는다. 관리 파일은 `링크: …`·`비밀번호: …` 두 줄의 글이다(예전 JSON 관리 파일도 읽는다). **불러오기**에서 링크와 비밀번호를 입력하거나 파일을 선택·드롭한다. 불러온 뒤 상단 띠의 **발행 관리**에서 수정, 발행 중단, 재발행, 삭제를 한다. 삭제해도 편집창 초안은 남는다. 새로 쓰기는 기존 발행 글과의 연결을 끊는다.

뷰어의 **작성자 수정**을 누르면 `/#edit={id}.{key}`의 fragment로 전체 링크를 편집실에 전달한다. 편집실은 주소에서 fragment를 지우고 비밀번호 확인 창을 연다. 비밀번호를 API에서 검증하고 본문 열쇠로 복호화한 뒤에만 불러오며, 기존 초안이 있으면 교체를 확인한다. 비공개 상태에서도 같은 링크에서 이 진입점을 제공한다. 비밀번호와 열쇠는 localStorage에 저장하지 않는다.

발행 전에는 전체 링크의 읽기 권한, 작성자 비밀번호의 관리 권한, 분실 시 복구 불가를 안내한다. 발행 중단 뒤에도 독자의 사본은 회수되지 않는다는 안내도 유지한다.

### 끝 장 카드 편집

하단 ‘끝 장 카드’로 바로 이동한다. 문구 기본값은 편집 제목(없으면 첫 문장)이며 별도 문구 120자까지 설정할 수 있다. ‘편집 제목을 카드 문구로’를 켜면 제목 연동으로 돌아간다. 글자 크기 28~120px, 문구 폭 30~90%, 가로·세로 위치 0~100%, 왼쪽·가운데·오른쪽 정렬을 조절한다. 위치는 카드 안전 영역 안에서 움직이며 드래그·방향키도 지원한다. 긴 문구는 카드 안에서 줄임표로 표시한다.

카드 문구를 바꿔도 편집 제목과 공개 제목은 바뀌지 않는다. 값은 `ending.text/size/width/x/y/align`에 저장하고 본문과 함께 암호화한다. 기본 바탕 값 `scene/ground`도 유지한다. 카드 아래 날짜 안내는 제거했고, 미리보기의 ‘이대로 발행하기’는 발행 단계로 이동한다. 카드 안의 작은 날짜 표기는 유지한다.

여기서 편집하는 것은 끝 장의 1200×630 카드다. 현재 서버 OG는 공개 제목 HTML이며, 크롤러용 `og:image` 업로드·공개 저장은 아직 구현하지 않았다. 카드 문구를 평문으로 서버에 보내거나 공개 이미지로 간주하지 않는다.

현재 비밀번호 재설정·분실 복구는 없다. 이미 독자가 받은 사본은 중단·삭제로 회수되지 않는다. 다른 창에서 먼저 수정하면 덮어쓰기를 거부하고 편집 중인 내용은 남긴다.

## Netlify 안에서 맡길 역할

- **정적 호스팅:** 편집실과 읽기 엔진의 HTML/CSS/JS. 프런트엔드는 번들하지 않는다. `npm run build`는 배포 컨텍스트 설정을 생성하고 공개 파일만 `dist/`에 복사한다.
- **Functions:** 생성·읽기·비밀번호 확인·수정·중단·삭제 API와 `/t/` 제목 메타 HTML. 기존 `netlify/functions/` 진입점과 사용자 흐름을 유지한다.
- **Blobs:** 암호문과 공개 제목, 비밀번호 해시, 게시 상태, 날짜, 버전을 저장한다. 브라우저가 저장소에 직접 쓰지 않고 Functions가 인증·입력 검증 뒤 접근한다.
- **외부 서비스:** 별도 DB·로그인·알림 서비스는 기본 구성에 넣지 않는다. 문의·관리 기능도 Netlify 안에서 우선 설계한다. 외부 연동은 꼭 필요한 경우에만 내부 대안과 비교해 별도 선택 사항으로 다룬다.

## Blobs 구현

- `server/store.mjs`가 API의 `get`·`change` 경계를 구현한다. 문서에는 `id, title, cipher, iv, salt, passwordHash, live, createdAt, updatedAt, revision`을 저장한다.
- 최초 생성은 `onlyIfNew`로 기존 주소 덮어쓰기를 막는다. 동일 생성 요청의 재시도는 기존 암호문·비밀번호가 일치할 때 같은 글을 돌려준다.
- 수정은 강한 일관성으로 읽은 ETag에 `onlyIfMatch`를 걸어 저장한다. 사용자 `revision`과 저장소 조건 중 하나라도 맞지 않으면 409다. ETag가 없으면 조건 없는 저장으로 우회하지 않는다.
- 삭제는 같은 조건으로 `{id, deleted:true}`만 남긴다. 본문 암호문·제목·비밀번호 해시는 제거하며 ID를 예약해 지연된 수정이나 재생성이 글을 되살리지 못하게 한다.
- 중단·삭제 상태는 강한 일관성 읽기로 확인한다. API와 `/t/` 응답은 `no-store`다.

### 저장소와 배포 컨텍스트

`scripts/deploy-config.mjs`가 빌드 환경을 검증하고 `scripts/build.mjs`가 `server/deploy-config.json`을 생성한다. 함수 번들에 이 설정을 포함하므로 함수 실행 시 빌드 전용 환경 변수에 의존하지 않는다.

| 컨텍스트 | 저장소 |
| --- | --- |
| production | `geuljari-articles-v1` — 같은 사이트의 재배포에도 유지 |
| deploy-preview / branch-deploy / Netlify dev | `geuljari-preview-{DEPLOY_ID}` — 배포마다 분리 |
| Netlify 밖 로컬 dev | `geuljari-local-v1` |

알 수 없는 Netlify 컨텍스트나 없는 배포 ID는 빌드를 실패시킨다. 브라우저 요청으로 저장소를 고를 수 없다. 미리보기 재배포는 새 저장소를 사용하므로 이전 미리보기 글이 새 배포에 이어지지 않는다. 이 이름 분리는 애플리케이션의 자료 혼용을 막는 용도이며, 같은 사이트의 신뢰된 함수 코드 사이의 권한 격리는 아니다.

공식 참고: [Netlify Blobs](https://docs.netlify.com/build/data-and-storage/netlify-blobs/). 별도 데이터베이스 계정이나 Firebase 설정 없이 Netlify가 제공하는 함수 실행 컨텍스트로 연결한다. 복잡한 목록·검색·집계는 후속 요구에 맞춰 별도 설계한다.

## 암호화와 공개 범위 — 현재 구현에서 유지

- 본문·조판값·분위기·날짜·끝 장 설정은 브라우저 WebCrypto AES-GCM 256으로 암호화한다. IV는 매번 12바이트 난수, 열쇠는 32바이트 난수다. AAD에 형식 버전과 ID를 묶는다.
- 본문 열쇠는 URL의 `#` 뒤에만 두고 API에 보내지 않는다. 공개 제목은 서버와 OG HTML에 평문으로 남는다. OG에는 본문이나 열쇠를 넣지 않는다.
- 수정 비밀번호는 HTTPS API에 전송하며 서버에는 무작위 salt + scrypt(N=32768, r=8, p=1) 해시를 저장한다. 응답에는 salt/해시를 노출하지 않는다.
- 비공개·삭제 글은 공개 API에서 404. 요청 크기·필드 길이·메서드·Origin 확인과 함수별 요청 제한을 유지한다.
- 편집실의 기존 초안은 브라우저 localStorage에 평문으로 보관한다. localStorage는 주소(origin)마다 따로라서 주소가 바뀌면 초안이 보이지 않는다. 헤더의 **글 파일 받기**로 받은 `.txt`(제목·처음 쓴 날, 표시가 든 본문, 글 전체 설정을 `이름: 값` 줄로)를 **불러오기**에 놓으면 그대로 돌아온다. 글 파일은 서버로 보내지 않는다(`geul-file.js`). 비밀번호·본문 열쇠는 localStorage에 넣지 않는다. 새로고침 뒤에는 다시 불러와야 발행 글을 관리할 수 있다.
- 공개 읽기 화면은 편집실의 저장 자료를 읽지 않는다. 열쇠가 없거나 틀리면 예시 글 대신 오류를 보여 준다.
- OG 이미지, 문의·관리자 화면, 비밀번호 복구, 만료·신고 정책은 이번 발행 구현에 포함되지 않았다.

## 운영 배포·확인

1. 통합 코드와 검증 결과를 main에 반영한다. Netlify 연결 저장소가 `m1r4d0r/geulteul`, 운영 브랜치가 `main`인지 확인한다.
2. `netlify.toml`의 `npm run build`, 공개 디렉터리 `dist`, 함수 디렉터리 `netlify/functions`, Node 22 설정으로 배포한다. 별도 Firebase 환경 변수는 사용하지 않는다.
3. 실제 Netlify에서 예시 글 발행·읽기·불러오기·수정·중단·재발행·삭제와 로그를 확인한다. 로컬 테스트 통과와 운영 검증은 구분한다.
4. 운영 글의 재배포 후 보존과 미리보기 분리를 확인한다. 사용량·백업·복구 정책은 후속 운영 과제로 남긴다.

Netlify 사이트 주소만 바꿀 때도 기존 사이트의 저장소 연결과 ID·열쇠를 보존하는지 확인한다. 새 Netlify 프로젝트를 만들면 데이터 이전이 별도 필요할 수 있다. 옛 링크 유지에는 기존 주소 유지나 리다이렉트가 필요하며 `#` 열쇠 보존도 확인한다.

## 파일과 검증 명령

- `publish.js/css`, `publish-crypto.js`: 발행·불러오기·암호화.
- `published.html/js/css`, `reader.js`: 공개 읽기 틀.
- `server/articles.mjs`, `server/store.mjs`, `server/reader-page.mjs`: API·저장소 어댑터·공개 제목 HTML.
- `scripts/deploy-config.mjs`, `server/deploy-config.json`: 검증된 배포별 저장소 선택.
- `netlify/functions/`: 실제 함수 진입점. `netlify.toml`: 공개 파일과 함수 배포 설정.

```sh
npm ci
npm test
npm run build
# Playwright가 설치된 검증 환경에서:
CHROMIUM=/path/to/chromium npm run test:publish-ui
python3 tests/smoke_margin_index.py /tmp/geulteul-margin-check
```

확인한 범위:

- `npm test`: API 검증과 실제 SDK 조건부 쓰기, 수정·삭제 경합, 삭제 후 주소 재사용 금지, 로컬 서버 재시작 후 보존, 운영·미리보기 저장소 분리.
- `npm run test:publish-ui`: 공식 로컬 Blobs 서버를 연결한 발행·복호화·잘못된 열쇠·중단·잘못된 비밀번호·관리 파일(줄글·JSON)·글 파일 받기/불러오기·불러오기·재발행·충돌·삭제와 모바일 UI.
- 여백 색인: 1280/390/320px 및 가로 화면. 읽기: PC·모바일, 끝 장·다시 읽기.
- `CHROMIUM=/path/to/chromium node tests/smoke_brand_effects.cjs`: PC·모바일 로고, 원고지·타자 렌더, 넘김 8종. 함수 esbuild 번들도 확인했다.

**로컬 서버 제한:** SDK 11.1.4의 로컬 `BlobsServer`는 읽기 응답에 ETag를 주지 않아 테스트 fixture에서 목록 응답의 ETag를 보충한다. 조건부 쓰기는 공식 SDK·서버로 실행한다. 운영 어댑터에는 이 우회가 없으며 ETag 없는 수정은 실패한다. 이 검증은 실제 Netlify 플랫폼의 권한·캐시·재배포 확인을 대체하지 않는다. 테스트 서버·보충 코드는 배포 함수에 포함하지 않는다.

`tests/studio-refinement.cjs`는 1280/768/390/320px·가로 화면에서 서랍, 카드 문구·배치 저장, 재열기, 발행 연결, 뷰어 작성자 진입·비밀번호 실패/성공·중단 후 관리 진입을 확인한다.
