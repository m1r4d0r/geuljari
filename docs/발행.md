# /t/ 발행

`codex/geuljari-margin-index`에서 구현했다. main 병합과 운영 배포는 하지 않았다.

## 쓰는 흐름

헤더의 **편집 → 미리보기 → 발행**에서 공개 제목, 수정용 비밀번호(8~128자), 발행 여부를 정한다. 전체 링크는 `/t/{id}#{열쇠}`다. 같은 글을 고쳐 저장하면 주소가 유지된다. 비밀번호는 독자에게 필요하지 않다.

발행 뒤 링크를 복사하거나 관리 파일을 내려받는다. 관리 파일에는 전체 링크와 비밀번호가 들어 있다. 헤더의 **불러오기**에서 링크와 비밀번호를 입력하거나 파일을 선택·드롭한다. 불러온 뒤 상단 띠의 **발행 관리**에서 수정, 발행 중단, 재발행, 삭제를 할 수 있다. 삭제해도 편집창의 초안은 남는다. 예시 글과 새로 쓰기는 기존 발행 글과의 연결을 끊는다.

현재 비밀번호 재설정·분실 복구는 제공하지 않는다. 이미 독자가 받은 사본은 중단·삭제로 회수되지 않는다. 다른 창에서 저장해 버전이 바뀌면 409로 덮어쓰기를 막으며, 사용자는 편집 중인 내용을 따로 보관한 뒤 다시 불러와야 한다.

## 운영 연결 — 아직 필요한 설정

1. Firebase 프로젝트에 Firestore 기본 데이터베이스를 만든다. 서버용 서비스 계정에 해당 데이터베이스 문서 읽기·쓰기 권한을 부여한다.
2. Netlify의 **Functions 범위 환경 변수**에 `FIREBASE_SERVICE_ACCOUNT`를 넣는다. 값은 서비스 계정 JSON 전체다. 저장소나 프런트엔드 파일에 넣지 않는다.
3. 선택 변수 `FIRESTORE_COLLECTION`은 기본 `geuljari_articles`다. 브랜치 미리보기는 별도 Firebase 프로젝트/계정과 컬렉션으로 분리한다. 운영 자격 증명을 신뢰할 수 없는 PR 미리보기에 노출하지 않는다.
4. Firestore 클라이언트 보안 규칙에서 발행 컬렉션의 직접 접근을 허용하지 않는다. 이 구현은 브라우저 Firebase SDK를 쓰지 않고 Admin SDK로만 접근한다. 기존 프로젝트의 다른 규칙을 덮어쓰지 말고 해당 컬렉션 규칙을 점검한다.
5. 이 브랜치의 Netlify 미리보기에서 `npm ci`, `npm run build`와 함수 배포를 확인한다. `netlify.toml`이 정적 공개 파일 복사와 API·읽기 함수를 구성한다. 별도 SPA 전체 경로 리라이트는 필요하지 않다.
6. 실제 `/t/` 주소를 다른 기기에서 열고, 중단·재발행·삭제와 환경별 저장소 분리를 확인한 뒤 운영에 병합한다.

현재 검증은 메모리 저장소를 주입한 로컬 HTTP 서버에서 했다. Firebase 자격 증명이 없어 실제 Firestore 트랜잭션과 Netlify 배포 경로는 아직 통합 검증하지 않았다. 저장소 설정이 없으면 API는 503을 반환하며 로컬 임시 저장을 발행 성공처럼 표시하지 않는다.

도메인을 바꾸어도 ID와 암호화 열쇠는 그대로다. 새 도메인의 편집실에 옛 전체 링크를 넣어 불러올 수 있다(같은 Firestore를 연결한 경우). 독자가 옛 주소로 계속 접근하려면 옛 도메인을 유지하거나 리다이렉트를 별도로 설정해야 한다.

## 데이터와 경계

- 서버 문서: `id, title, cipher, iv, salt, passwordHash, live, createdAt, updatedAt, revision`.
- 본문·조판값·분위기·날짜·끝 장 설정은 브라우저 WebCrypto AES-GCM 256으로 암호화한다. IV는 매번 12바이트 난수, 열쇠는 32바이트 난수다. AAD에 형식 버전과 ID를 묶는다.
- 본문 열쇠는 URL fragment에만 두고 API에 보내지 않는다. 공개 제목은 서버와 OG HTML에 평문으로 남는다. OG에는 본문이나 열쇠를 넣지 않는다.
- 수정 비밀번호는 HTTPS API에 전송하고 서버에서 무작위 salt + scrypt(N=32768, r=8, p=1)로 해시한다. 응답에는 salt/해시를 노출하지 않는다.
- API 응답과 `/t/` HTML은 `no-store`. 비공개·삭제 글은 공개 API 404. 요청 크기·필드 길이·메서드·Origin 확인, 함수별 IP/domain rate limit을 둔다.
- 편집실의 기존 초안은 계속 브라우저 localStorage에 평문으로 보관한다. 비밀번호·본문 열쇠는 localStorage에 넣지 않는다. 새로고침 후에는 다시 불러와야 발행 글을 관리할 수 있다.
- 읽기 화면은 기존 편집실 저장소를 읽지 않고 복호화한 문서만 사용한다. 열쇠가 없거나 틀린 경우 예시 글로 대체하지 않고 오류를 보여 준다.
- 생성 응답이 유실돼 같은 요청을 재시도하면 같은 문서로 응답한다. 수정·삭제는 revision 트랜잭션으로 동시 변경을 감지한다.
- OG 이미지 생성, 문의·관리자 화면, 비밀번호 복구, 만료·신고 정책은 이번 구현 범위 밖이다.

## 파일과 확인

- `publish.js/css`, `publish-crypto.js`: 발행·불러오기와 암호화.
- `published.html/js/css`, `reader.js`: 공개 읽기 틀. 기존 읽기 엔진을 재사용한다.
- `server/articles.mjs`, `server/store.mjs`, `server/reader-page.mjs`: API, Firestore 트랜잭션, 공개 제목 HTML.
- `netlify/functions/`: 실제 함수 진입점. 서버 의존성은 `firebase-admin`만 사용하며 프런트엔드 번들은 만들지 않는다.

```sh
npm ci
npm test
npm run build
# Playwright가 설치된 검증 환경에서:
CHROMIUM=/path/to/chromium npm run test:publish-ui
python3 tests/smoke_margin_index.py /tmp/geulteul-margin-check
```

브라우저 검증은 저장소의 예시 글로 발행·복호화·잘못된 열쇠·중단·잘못된 비밀번호·관리 파일·재발행·동시 수정 충돌·삭제, 1280/390/320px 레이아웃을 확인한다. 테스트 메모리 저장소는 배포 함수에 포함하지 않는다.
